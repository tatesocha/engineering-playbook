Agent workflow, code to reproof

Every step from code to a bug recreated after its fix. Solid steps run today. Dashed steps are planned and not yet built.

built and running planned, not built reproof loop
  1. 1

    Code inception

    Tracked item, owner, premise checked

    • Premise verified against code or data before routing
    • One named owner per item
  2. 2

    Build and open the PR

    Draft PR, tracked ID in title, type line

    • Labels set from the PR body. Risk tier set by a workflow
    • Repro shown FAILING before a fix, for bug work (device-bug checklist)
  3. 3

    Verify

    Typecheck, guards, required CI checks

    • Typecheck and every guard script
    • Copilot automatic review. Review threads answered and resolved
  4. 4

    Validate

    Walk it, compare it to the design, record what cannot be simmed

    • Simulator walk. Design parity against the approved frame
    • Anything the simulator cannot test is CANNOT BE SIMMED and goes to a device
  5. 5

    Merge by risk

    Risk tier workflow and the sweep

    • risk: low auto-merge, once required checks pass. Docs, scripts and tests
    • risk: medium app code. An agent merges after the sweep, one line reported. Tier in review, not yet live
    • risk: high a human decides
  6. 6

    Ship and watch

    EAS build, TestFlight, web deploy, PostHog and Sentry

    • Production writes need a human go-ahead. No agent deploys on its own
    • Weekly low-risk revert rate in weekly revert-rate job
  7. 7

    Error capture

    built app_error in PostHog, Sentry event, ErrorBoundary

    • Name and screen only. No message, props or user id
  8. 8

    Error intake into the tracker

    planned tracked item

    • Target: one tracked item per error cluster, filed by a scheduled routine
  9. 9

    Real-time fix, named owner

    planned tracked item

    • Triage routine files one tracked item per cluster (read-only)
    • Fan-out: one remote cloud session per item, branch claude/error-fix-ON-id, draft PR. Cap of 3 at once
    • Serial only: migrations, edge and web deploys, anything that writes production. human go-ahead first
    • Owner: one agent per fix, from reproduction through merge. A human approves dispatch
    • Rollback path: revert PR under the same risk rule, or the previous web deploy or edge-function version
  10. 10

    Reproof

    Recreate the bug on the fixed build and show it gone

    • Same repro as step 9, now PASSING on the fixed build
    • Done only after both the failing and the passing proof are linked

Reproof loop

A fix that is merged but not reproofed is not done. If the bug is still there, step 10 sends the item back to step 9 (fix) with the new evidence. It never goes to step 5 (merge) while the repro still fails. The loop closes only when the bug is recreated on the fixed build and does not occur.

Rollback paths

App build: a revert PR, with a "Reverts" line naming the PR in the body, merged under the same risk rule. Counted by a weekly revert-rate job.
Web: The web deploy script redeploys the previous commit when a probe fails.
Edge function: redeploy the previous version. Production writes need a human go-ahead.
