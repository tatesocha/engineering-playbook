Case study 2 · Business problem

Done means checked, not claimed.

A short checklist, ticked before work goes back to the decision maker, cuts the half-finished returns.

The problem, in one line. Work kept coming back half-finished, or the same question was asked twice.

Why it matters. Handoffs fail quietly. The person receiving the work spends time finding what the sender skipped, and the same question returns. Any team with reviews, approvals or agent work has this loss.

What we did

Standard

Say what done looks like

One line, written before starting.

Premise

Verify before reporting

A query, read or run, with the result quoted.

Ledger

Report counts by state

Closed, open, partial, killed, and fell off, named and never silent.

Rules that come with it

  • Links, always. Every task, document and change named is a link.
  • Never re-ask. If the decision maker already picked, the pick is passed on.
  • Unticked lines carry a reason. If a line cannot be ticked, the reason is written beside it.

The trade-off, stated plainly

  • A checklist adds a few minutes to every handoff.
  • A ticked box can still hide a weak check. The quoted evidence is the part that counts.
  • Checklists go stale if nobody revisits them. Each one has a short, named owner.
Why it matters, again. The gate moves the cost of checking from the decision maker to the person who did the work, which is where it belongs.

Where else this shows up

  • Sales handoffs, legal review, audit workpapers.
  • Decision: one checklist per work type, owned by whoever receives the work.
  • Owner: the receiving reviewer keeps the list honest.
